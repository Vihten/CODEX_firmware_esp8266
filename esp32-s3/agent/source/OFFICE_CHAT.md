# Офісний чат

## Взаємна перевірка двох ПК

Для прямого чату встановіть агент на обох ПК в одній локальній мережі. Для налаштування вхідних з’єднань скористайтеся інструкцією [Direct peer chat on Windows](DIRECT_PEER_INSTALL.md).

1. На обох ПК відкрийте **Офісний чат → Перевірити комп’ютери**. Кнопка **Скопіювати ID та відбиток** копіює публічний ID цього ПК та всі 64 символи SHA-256 групами по чотири.
2. Обміняйтеся цими даними особисто, телефоном або через уже перевірений канал. На першому ПК виберіть другий за його ID. У полі під мережевим відбитком вставте отриманий рядок або введіть відбиток зі слів власника. Натисніть **Підтвердити ПК**, коли дані збігаються.
3. На другому ПК повторіть перевірку для першого. Для наступних запусків агент зберігає підтвердження. Якщо список порожній, перевірте, що обидва агенти запущено, і натисніть **Оновити список**.

## Після перевстановлення Windows на іншому ПК

Якщо для знайомого ID змінився відбиток, агент блокує заміну. Попросіть власника відкрити **Перевірити комп’ютери** на перевстановленому ПК та незалежно звірте його ID й усі групи нового відбитка. Якщо власник не підтверджує зміну, залиште прив’язку на місці.

1. На кожному ПК, що раніше довіряв цьому ID, увійдіть як користувач агента. У Провіднику відкрийте `%LOCALAPPDATA%\CodexLanAgent\chat\trusted` і ввімкніть показ розширень файлів.
2. Знайдіть один файл із **ID віддаленого ПК** в назві. Наприклад, для ID `00AB12CD` це `00AB12CD.json`. Відкрийте його для читання й перевірте поля `id`, `name` та старий `fingerprint`. Перейменуйте саме цей файл на `00AB12CD.json.revoked`, підставивши фактичний ID. Агент перечитає каталог і відкличе стару прив’язку. Запис нового відбитка виконується через явне підтвердження у вікні агента.
3. Натисніть **Оновити список**, виберіть перевстановлений ПК, введіть незалежно отриманий новий відбиток і натисніть **Підтвердити ПК**. На перевстановленому ПК підтвердьте кожного співрозмовника у зворотному напрямку. Якщо після перевстановлення сам ID теж змінився, відкличте запис старого ID та перевірте новий ID як окремий ПК.

## Підключення табло

1. Оновіть прошивку контролера через його вебсторінку.
2. На вебсторінці контролера відкрийте **Агенти → Підключення**, виберіть потрібний ПК і натисніть **Оновити** один раз. Залиште ПК увімкненим. Для сумісних старих версій контролер спочатку запропонує проміжне оновлення, а потім версію з чатом. Завершення підтверджує сам агент після запуску.
   Якщо картка вказує на необхідність ручного оновлення, розпакуйте `bootstrap.zip` на цьому ПК та запустіть `update_codex_lan_agent.cmd` з облікового запису Windows, у якому працює агент. Для першого встановлення використайте `install_codex_lan_agent.cmd`.
3. Біля годинника Windows відкрийте приховані значки. Правою кнопкою натисніть **Офісний чат → Підключити табло**.
4. Скопіюйте ключ із вікна агента й натисніть **Відкрити форму контролера**. Якщо браузер попросить увійти, увійдіть і повторно відкрийте форму з вікна агента. Звірте ідентифікатор ПК, вставте ключ і підтвердьте підключення. Звичайний перезапуск контролера зберігає цю прив’язку.

## Повідомлення

Натисніть значок чату лівою кнопкою. На схемі кабінету виберіть один або кілька столів. Ваше місце позначене **Ви**. Щоб текст побачили на загальній матриці, виберіть також **Табло**. Табло можна вибрати й окремо.

Натисніть **Написати**, введіть текст і натисніть **Надіслати**. Лічильник показує розмір тексту в байтах UTF-8. Максимум для одного повідомлення становить 512 байтів.

На вибраних ПК повідомлення з’явиться справа внизу. Прочитати його знову можна через **Отримані повідомлення** в меню значка. На табло текст прокручується з іменем відправника. Під час пріоритетної індикації прокручування чекає.

Після надсилання під полем повідомлення з’явиться окремий рядок для кожного отримувача. У компактному вікні натисніть **Результати надсилання**. Стан **очікує** означає, що агент ще не має підтвердження. **Доставлено** означає, що ПК або контролер підтвердив приймання. Якщо показано **доставку не підтверджено**, повідомлення могло дійти. Звіртеся з отримувачем перед повтором.

Для частково невдалої доставки виберіть у меню значка **Відновити непідтверджене повідомлення**. Перегляньте результати для кожного адресата. Під час відновлення всі позначки вибору знято, а адресати з підтвердженою доставкою недоступні для повтору.

Прямі з’єднання між ПК використовують TLS із перевіркою підтверджених відбитків. Окремий канал табло передає текст локальній мережі через HTTP із підписом. Контролер тримає прийняті повідомлення до десяти хвилин, а перезапуск очищає його чергу.
